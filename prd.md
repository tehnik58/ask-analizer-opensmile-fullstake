# PRD: Сервис анализа уверенности перевода (MVP)

## 1. Обзор продукта (Product Overview)
**Название:** Translation Confidence Analyzer (TCA)
**Суть:** Веб-сервис для тестирования гипотезы оценки качества перевода студентов. Позволяет загрузить оригинал аудио и несколько вариантов перевода, получить оценку уверенности речи и визуально сравнить акустические характеристики (графики OpenSMILE) синхронно с воспроизведением аудио.

---

## 2. Функциональные требования (Functional Requirements)

### FR-1: Загрузка аудио
- Пользователь может загрузить **1 аудиофайл** (Оригинал).
- Пользователь может загрузить **N аудиофайлов** (Переводы студентов).
- Поддерживаемые форматы: `.wav`, `.mp3` (приведение к wav 16kHz моно на бэкенде).
- Ограничение размера: до 20 МБ на файл.

### FR-2: Анализ данных (OpenSMILE)
- Система автоматически запускает извлечение признаков через OpenSMILE для всех загруженных файлов.
- Извлекаются два типа данных:
  - **Functionals (статистика)**: для итоговой оценки уверенности.
  - **LLD (Low-Level Descriptors, временной ряд)**: для построения графиков.

### FR-3: Оценка уверенности
- На основе статистических признаков (Jitter, Shimmer, дисперсия F0, громкость) система вычисляет скор (0-100).
- Система выдает лейбл:
  - `> 70` → **Уверенно** (Зеленый)
  - `40 - 70` → **Средне** (Желтый)
  - `< 40` → **Неуверенно** (Красный)

### FR-4: Воспроизведение и Визуализация
- Пользователь может нажать Play на оригинале или любом переводе.
- Во время воспроизведения под аудиоплеером отображается интерактивный график (диаграмма) признаков OpenSMILE.
- На графике отображается **каретка времени**, движущаяся синхронно с аудио.
- Возможность выбрать отображаемые метрики на графике (чекбоксы): F0 (высота голоса), Loudness (громкость), Jitter (дрожание).

## 4. Архитектура и Технологии

### Бэкенд (Python)
- **Фреймворк:** FastAPI (быстрый, удобный для статики и JSON).
- **Обработка аудио:** `opensmile` (Python-обертка), `librosa` (конвертация/mp3->wav).
- **Хранение:** Локальная файловая система (для MVP достаточно).

### Фронтенд (JavaScript)
- **Фреймворк:** React + Vite (или Vue).
- **Графики:** `Chart.js` или `Recharts` (нужна возможность рисовать вертикальную линию-каретку по оси X).
- **Аудио плеер:** `Howler.js` (удобно связывать время аудио с состоянием React).

## 5. API Спецификация

### `POST /api/upload/`
Запуск сессии анализа.
**Request (form-data):**
- `original`: file
- `translations`: list[file]

**Response:**
```json
{
  "session_id": "uuid-123",
  "status": "processing"
}
```

**Response:**

## 6. Логика OpenSMILE (Детали реализации)

Для решения вашей задачи нужно извлекать признаки **на двух уровнях**:

### Шаг 1: Извлечение временных рядов (LLD) — для графиков
Мы не можем использовать стандартные конфиги (emobase), так как они отдают только статистику (mean, std). Нам нужны значения кадр за кадром (frame-by-frame).

```python
import opensmile

# Конфиг для извлечения низкоуровневых дескрипторов (LLD) без статистики
smile_lld = opensmile.Smile(
    feature_set=opensmile.FeatureSet.eGeMAPSv02,
    feature_level=opensmile.FeatureLevel.LowLevelDescriptors, # ВАЖНО!
)

def get_time_series(audio_path):
    df = smile_lld.process_file(audio_path)
    # df будет содержать колонки времени и значения F0, Loudness на каждый кадр (обычно 10мс)
    return {
        "F0": df['F0semitoneFrom27.5Hz_sma3'].tolist(),
        "Loudness": df['Loudness_sma3'].tolist(),
        "Jitter": df['jitterLocal_sma3nz'].tolist()
    }
```

### Шаг 2: Извлечение статистики (Functionals) — для скоринга уверенности
```python
smile_func = opensmile.Smile(
    feature_set=opensmile.FeatureSet.eGeMAPSv02,
    feature_level=opensmile.FeatureLevel.Functionals, # Статистика за весь файл
)

def get_confidence_score(audio_path):
    df = smile_func.process_file(audio_path)
    features = df.iloc[0]

    # Извлекаем нужные стат. признаки
    f0_std = features['F0semitoneFrom27.5Hz_sma3nz_stddevNorm']
    jitter_mean = features['jitterLocal_sma3nz_mean']
    loudness_std = features['Loudness_sma3_stddevNorm']

    # Эвристическая формула (требует настройки на реальных данных!)
    # Чем выше stddev (разброс) и jitter (дрожание) -> тем ниже уверенность
    score = 100 - (f0_std * 40 + jitter_mean * 1000 * 30 + loudness_std * 30)

    return max(0, min(100, score))
```

## 7. Нестандартные кейсы и ошибки (Edge Cases)

1. **Тишина в аудио:** OpenSMILE вернет `NaN` или `0` для F0 (голос отсутствует). На графике это должны быть "разрывы" линии, а не падение в ноль. Фронтенд должен уметь рисовать `null` значения как пропуски.
2. **Разная длина аудио:** Оригинал 10 сек, перевод 15 сек. Графики должны масштабироваться под свою длину. При наложении графиков друг на друга (опционально) нужно нормализовать ось X (0% - 100% длительности).
3. **Фоновый шум:** Если студент записал перевод на плохой микрофон, Jitter и Loudness будут высокими, что даст ложную оценку "Неуверенно". Для MVP это нормально, но стоит выводить предупреждение: *"Запись шумная, оценка может быть неточной"*.
